Six callbacks, three pairs

Do not make them memorise the ring. Three pairs carry the whole idea, and each pair answers one question about the activity.

Say this out loud“Born and dies. Visible or not. Interactive or not.”

onCreate() ⇄ onDestroy()

created or destroyed

Fires once per activity instance. This is the pair that decides whether the object exists at all.

onStart() ⇄ onStop()

visible or not

The user can see the screen, or cannot. The object is still alive during onStop() — just off screen.

onResume() ⇄ onPause()

interactive or not

Does the activity have the focus? A dialog on top takes the focus without hiding the activity.

Because the activity never went through onStop() on its way down.

Rotation is a configuration change: Android takes the activity down to onDestroy() and builds a new one. onRestart() only fires when an existing, still-alive activity comes back from onStop() — which is exactly the Home-and-return case.

Run both paths in the simulator and compare the log. That difference — onRestart() present or absent — is the single fastest way to tell which of the two happened.
